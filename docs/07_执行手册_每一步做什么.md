**三步循环**：做 → 对照「预期结果」→ 记录（更新 `docs/06` 与 `进度.md`）。

- **测试集只评一次**：选 k、选方案、选 prompt 一律在验证集做；测试集只用来报最终数字。
- 步骤编号 `S01` 与 `进度.md` 的「当前步骤」对应，换 AI 时按编号接续。

### S21 · ★ forward hook 基础
`W1` · 3 小时 ★★ 本周最重要

**做什么**：对一个简单模型注册 `register_forward_hook`，在 hook 里打印输出的 shape 并 `return None`。

```python
feats = {}
def hook(module, inp, out):
    feats['x'] = out
    # return None → 不改变前向结果
h = model.some_layer.register_forward_hook(hook)
```

**预期结果**：前向一次后 `feats['x']` 里有该层输出；且**模型原本的输出完全不变**（用数值确认）。

**不符合预期**：hook 没触发 → 检查是不是在 `no_grad` 下注册的（`no_grad` 不影响 hook）；输出变了 → hook 里错误地 `return` 了一个张量。

**产出**：`code/notebooks/w01_hook_basics.ipynb`

## 第 5 周（W5）：前景掩码 · 换景样本 · 换景分数 · 背景识别基线

### S47 · 生成前景掩码
`W5` · 3 小时

**做什么**：
1. 用 CUB-200-2011 的 `segmentations/`，按 `metadata.csv` 的 `img_filename` 复制成 `data/raw/waterbirds/segmentations/<同名>.png`；现成脚本 `code/scripts/02_make_masks.py`。

3. 逐像素校验：抽 20 张，掩码内像素应与 CUB 原图逐像素相等（差值 < 1e-6）；掩码外区域应与 CUB 原图不同（被背景替换）。

**预期结果**：掩码数量 = metadata 行数，无缺失；抽样校验全部通过；覆盖率中位数落在合理区间（记录实测值）。

**产出**：`data/raw/waterbirds/segmentations/` + `data/raw/_mask_report.txt`

### S48 · 构建同前景换景样本
`W5` · 4 小时

**做什么**：
1. 换景公式：`I_swap = I × mask + B_donor × (1 − mask)`；先确认 mask 已归一化到 0/1（CUB 原图是 0/255，要除以 255）；**前景像素必须与原图逐像素相同**。
2. donor 背景：取对侧类别的图 → 用它的掩码把鸟区置黑 → inpainting 修补鸟区 → 只保留背景。
   **不能**直接拿对侧原图当背景，会把第二只鸟贴进去，换景分数直接作废。
3. 两个方向：`landbird` 原图（陆地）→ 水面背景；`waterbird` 原图（水面）→ 陆地背景。
4. 固定种子，val / test 都生成，逐条记录 `img_filename → donor 文件名`。

**预期结果**：两个方向各生成一批样本（数量记录实测值）；换景后鸟区像素与掩码外区域分别来自原图与 donor；同一 `img_filename` 结果可复现（同种子同 donor）。

**不符合预期**：鸟边缘出现"鬼影" → donor 的鸟没去干净，重做 inpaint；前景被背景覆盖 → mask 的 0/255 或通道数错。

**产出**：`code/src/data/swap.py` + `data/processed/swaps/{to_water,to_land}/`

### S49 · 换景质量检查
`W5` · 2.5 小时

**做什么**：
1. **覆盖率 5%~60%**：低于 5% 背景几乎没变，高于 60% 鸟被切掉。
2. 每个方向 **≥30 张人工目检**：鸟完整、背景确实是水/陆、无明显接缝。
3. donor 必须与原图**不同源**（不能是同一张图，也不能共用同一 `place_filename`）。
4. **边缘羽化**：掩码做 3~5 像素高斯羽化再合成，避免硬边。
5. 不达标样本列入排除清单，报出排除率。

**预期结果**：两个方向各 ≥30 张通过目检；排除率记录实测值；排除清单落 csv。

**不符合预期**：排除率过高（>20%）→ 回头查掩码质量与 donor 去鸟是否彻底，别急着算分数。

**产出**：`code/results/csv/swap_qc.csv` + `code/results/figures/swap_qc_grid.png`

> ⚠️ 阶段二第二个硬检查点：换景样本不过关，S50 的分数直接作废。

### S50 · 换景分数计算
`W5` · 3 小时

**做什么**：
1. `margin_y(I) = s_y(I) − s_¬y(I)`，`s` 用 S44 的同一套打分（同 prompt、同归一化）。
2. `Δ_d = mean[margin_{y_d}(原图) − margin_{y_d}(换景图)]`，按方向 d 分别算。
3. **翻转率** = 换景后被判成"背景一致类别"的比例（水鸟换到陆地后被判 landbird 的比例等）。
4. val / test 分开算；换景样本**只用于评测**，不参与选头、选 k、调 prompt。

**预期结果**：两方向各一组 Δ 与翻转率（记录实测值）；Δ > 0 表示"换背景后正确类别更没优势"，即该方向捷径更强；两个方向的 Δ 可以不一样大。

**不符合预期**：Δ 接近 0 → 换景没起作用（覆盖率太低或 donor 与原地背景太像）；Δ 为负 → 检查 margin 的类别下标有没有取反。

**产出**：`code/results/csv/swap_score.csv`（列：方向、split、Δ_margin、翻转率、n）

### S51 · 背景识别探针基线
`W5` · 3 小时

## 第 7 周（W7）：LTC 评分复现

### S54 · 跑通 TextSpan/LTC 分解与 Logit Lens（先 demo）
`W7` · 4 小时

**做什么**：
1. 先原样跑通 TextSpan 官方实现（GitHub 检索 `clip_text_span`），不要急着改。
2. LTC 论文未给代码链接，按论文公式自己实现最小版。
3. 分解：CLS 表示 = z0 + Σ MSA_l + Σ MLP_l；头状态 `ẑ_{l,h} = Σ_i z̃_{l,h,i}`（对 token 聚合）。
4. Logit Lens：`LL(l,h,y) = <P_I(ẑ_{l,h}), P_T(E_T(y))>`。
5. 先在一张小图上验形状：12 层 × 12 头 = 144 个头，每头 64 维。

**预期结果**：demo 能打印分解后的组件贡献；144 个头全部有值、无 NaN；同一张图两次运行结果一致。

**不符合预期**：依赖冲突 → 在 `clipbg` 里装它要求的版本；跑不通 → 按论文附录自己实现最小版，不要卡在官方仓库。

### S55 · 手推 LTC 式 (5)~(10)
`W7` · 3 小时

**做什么**：
1. direct effect：`v_{l,h} = LL(l,h,ŷ) − LL(l,h,ȳ)`（预测类 vs 另一类）。
2. 稀疏化：每个样本取 argmax 的 `(l,h)` 置 1，其余 0；在数据集上平均并归一化，得稀疏集合 P*。
3. 正/负子组：G_P（背景与类别正相关，多数组）与 G_N（不匹配，少数组）；LTC 只在 G_N 上对比。
4. γ 阈值与 `V_S = σ(V_NW − V_NC)`（σ 为 1(V > γ)）。
5. mean ablation：把选中头状态替换为数据集均值；LTC 称零消融与均值消融无差别，**我们要在本数据上自己验证**。
6. knowledge injection（KI）：用大模型生成类别判别文本方向后做正交投影。本课题**只在精读里理解**，不作为主实验（主实验只有 mean ablation），要试就放到 S74 的消融里试。

**预期结果**：能把 LTC 流水线画成 5 个方框并逐条对上式号；能解释"为什么只在 G_N 上对比"；能说清 γ 怎么定、调 γ 会怎样；能说清 KI 与 mean ablation 的区别，以及本课题为什么不做 KI。

**产出**：`paper/05_文献/笔记_LTC公式推导.md`（含手写推导照片）

## 第 10 周（W10）：抑制实现 · 验证集选方案 · M3

### S60 · 实现 mean ablation（主）/ zero / scale
`W10` · 4 小时

**做什么**：
1. 主操作 **mean ablation**：把选中 `(l,h)` 的状态替换为该数据集上的均值；均值在训练集或验证集上算好并缓存，**不能每批现算**。
2. 备用：zero ablation、scale=0.5。
3. hook 只改目标头的 64 维切片，其余头与残差流不动。
4. 写开关：`enabled=False` 时必须与不挂 hook 完全一致。

**预期结果**：抑制 1 个头后 logits 变化；关闭开关时 logits 与基线 `torch.equal` 为 True；均值缓存可复用。

**不符合预期**：开关不一致 → hook 里设备/dtype 不一致，或错误 `return` 了修改后的张量；形状报错 → 拼回前忘了 `reshape`。

**产出**：`code/src/intervene/ablate.py`

### S61 · 实现单独抑制、并集抑制、LTC 原方案、随机抑制
`W10` · 4 小时

**做什么**：
1. 单独：`P_S^water` top-k、`P_S^land` top-k。
2. 并集：`U = P_S^water ∪ P_S^land` **先去重**，再按并集分数取 top-k；若 `|U| < k`，把 k 降到 `|U|` 并重跑其他组。
3. LTC 原方案：`P_S^LTC` top-k（合并负组）。
4. 随机：同 k、同操作，只随机换头，≥3 seeds。
5. 四个模块共用同一 hook 与同一套开关；头集合用哈希记录。

**预期结果**：四条链路都能跑通并输出准确率；四个模块在开关关闭时都等于基线（`torch.equal` 为 True，见附录 B 第 5 条）；并集与 LTC 在相同 k 下实际抑制头数一致（S66 会查）；每个 run 落 `run_id`、k、头集合哈希、种子。

**不符合预期**：并集去重后不足 k → 按规则降 k，**不许偷偷补随机头**；随机组头数不一致 → 传参错。

## 附录 D：术语与口径（写论文、汇报统一用这套）

| 术语 | 含义 |
|---|---|
| 水面捷径 | `landbird_on_water`：陆鸟在水面 → 被误判为水鸟 |
| 陆地捷径 | `waterbird_on_land`：水鸟在陆地 → 被误判为陆鸟 |
| `P_S^water` / `P_S^land` | 只用水面 / 陆地负组分别选出的候选头集合 |
| `P_S^LTC` | 两类负组合并后选出的头集合（LTC 原口径） |
| 并集 `U` | `P_S^water ∪ P_S^land`，去重后按分数取 top-k |
| 同 k | 六组干预抑制的头数完全一致，只换"选哪几个头" |
| 换景分数 | 正确类别 margin 的变化量（可正可负），**不是准确率** |
| mean ablation | 把选中头状态换成数据集均值（主实验的中间激活消融） |
| B1 / B2 / B3 | 背景识别三口径：原图 / 去前景背景图 / 独立场景图 |
| 最差组准确率 | 四组准确率的最小值，不是"少数组平均" |
