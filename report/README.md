# report/ — 每周进度汇报文档

## 命名规则

```
W<两位周次>_<汇报日期 YYYY-MM-DD>_<主题>.docx
```

例：`W03_2026-11-24_进度汇报.docx` = 第 3 周、2026-11-24 汇报。
周次以 `进度.md` 为准（**新版 27 周制：第 1 周锚定 2026-11-23 当周**）；同一周重交用同日期覆盖，换日期另存。

> 历史说明：`W03_2026-11-24_进度汇报.docx` 是按旧 26 周口径（W1=2026-11-09）编号的；
> 新版 27 周下 2026-11-24 属于第 1 周。该文件已由用户手改定稿，**保留原名不改**，避免覆盖；
> 下一次汇报从 `W02_<日期>_...` 起按新口径编号。

## 写作规范（2026-11-24 用户确认，之后都按这个）

1. **只写本周做了什么**。默认只保留「一、本阶段完成的工作」这一节，需要时再分 1.1 / 1.2。
2. **不写**：摘要、课题名称/汇报人/日期之类的元信息块、下一步计划、小结、没有数据支撑的展望。
3. **「对题目的理解」只在第一次汇报写**，之后不重复。
4. **简洁优先**：一句话能说清就不写两句；不加封面页、彩色强调、图标、装饰线。
5. **保留**页眉（文档名 + 周次 + 日期）、页脚页码；有数据才放表格和图。
6. 第一人称客观陈述，写「做了什么、得到什么数」，不写「我认为」「我们计划」。

## 排版

沿用 `tools/docx_kit.py` 的既有样式，与 `docs/00`~`05` 一致：
A4、页边距 2.4/2.2/2.5/2.3 cm、正文宋体小四、1.5 倍行距、黑体标题、
表头浅蓝底纹、页脚页码、页眉一行。标题 22pt 加粗，一级标题 17pt，二级标题 13.5pt。
